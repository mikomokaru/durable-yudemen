# 既定反転の終着点手順（`ACCESS_REQUIRED` の既定を `"1"` へ）

本書は、段階的有効化の**移行期**（デプロイ時オーバーライドで本番だけを ON にしている状態）から、**終着点**（リポジトリ既定を ON に据え、オーバーライドなしの素のデプロイでも認証が ON を保つ状態）へ移行するための手順である。この反転をもって「オーバーライドを伴わない素のデプロイが認証を黙って OFF に戻す」footgun を**構造から取り除く**（要件 5.7）。

- **spec**: cloudflare-access-enablement
- **対応タスク**: 9.4 既定反転の終着点手順を整備する ［手続き］
- **充足要件**: 5.7（既定反転の終着点・`.dev.vars` でローカル OFF 維持）
- **正本**: `.kiro/specs/cloudflare-access-enablement/design.md`（B. Deployment_Config「既定反転の終着点とローカル開発の手当て」）／`requirements.md`（Requirement 5.7・文脈として 5.6）／`.kiro/steering/tooling.md`（`wrangler.jsonc` が Workers 設定の単一の正本・vars 変更後は必ず `pnpm cf-typegen`）
- **姉妹文書**: 移行期の手当ては `wrangler.jsonc` の `vars` コメント（タスク 6.1）と本番切替手順（タスク 8.2）が担う。本書はその**恒久対処**にあたる。

> **⚠ この手順は「いつでも実行してよい編集」ではない。** `wrangler.jsonc` / `.dev.vars` の編集そのものはコードだが、**反転の実行可否は運用判断**（本番が安定運用に達したかの判断・§2）である。判断基準（§2）を満たす前に反転してはならない。本書を読んだ時点でまだ移行期であれば、編集は行わず §2 のゲートを待つ。**アプリコードのロジックは一切変更しない**（切替は `vars` の値のみ・コード分岐は不変・要件 10.1）。

---

## 0. なぜ反転するのか（移行期と終着点の違い）

| 局面 | `wrangler.jsonc` の既定 `ACCESS_REQUIRED` | 本番の ON 手段 | 素のデプロイ（オーバーライドなし）の帰結 | 位置づけ |
| --- | --- | --- | --- | --- |
| **移行期**（現状・要件 5.6） | `"0"`（OFF） | デプロイ時オーバーライドで `"1"` | **認証 OFF に戻る**（footgun を移行期に限り受容） | 段階的有効化の手段。恒久状態にしない |
| **終着点**（本書・要件 5.7） | `"1"`（ON） | 既定が ON ゆえオーバーライド不要 | **認証 ON を保つ** | オーバーライド依存を解消した最終形 |

移行期は「本番のみ ON・リポジトリ既定は OFF」という非対称を、デプロイ時オーバーライドという**運用者の記憶と手作業**に頼って維持している。この依存が続く限り、オーバーライドを忘れた素のデプロイが認証を黙って OFF に戻す退行余地が残る。既定を `"1"` へ反転すれば、この退行余地は構造から消える（真 — 既定が真実を語る／善 — 運用者を手作業の footgun から守る）。

反転後に残す非対称は「**本番 ON・ローカル OFF**」だけであり、これは `.dev.vars` によってローカル側に明示的に固定する（§1 手順 2）。ローカルは合鍵 URL（推測困難な Store_Path の直叩き）相当で開発を継続できる。

---

## 1. 反転の編集手順（§2 のゲート通過後にのみ実行）

以下は §2 の実行可否判断を満たしたあとにのみ行う。編集対象は 2 ファイル（`wrangler.jsonc` と `.dev.vars`）で、両者は**同時に**変更する（本番 ON とローカル OFF 固定は一対の操作）。

### 手順 1. `wrangler.jsonc` の既定を `"1"` へ反転する

`wrangler.jsonc` の `vars.ACCESS_REQUIRED` を現在の `"0"` から `"1"` へ変更する。

現在（移行期）:

```jsonc
"vars": {
  "OBSERVE_DEBUG": "0",
  "ACCESS_REQUIRED": "0",
  "TEAM_DOMAIN": "https://<team>.cloudflareaccess.com",
  "POLICY_AUD": "<access-app-aud>"
}
```

反転後（終着点）:

```jsonc
"vars": {
  "OBSERVE_DEBUG": "0",
  "ACCESS_REQUIRED": "1",
  "TEAM_DOMAIN": "https://<team>.cloudflareaccess.com",
  "POLICY_AUD": "<access-app-aud>"
}
```

あわせて `ACCESS_REQUIRED` 上部のコメントを終着点の記述へ更新する。移行期のコメントは「既定 `"0"`（OFF）を保つ／本番はデプロイ時オーバーライドで ON にする／恒久対処は既定反転」という趣旨で書かれているため、反転後は「**既定 `"1"`（ON）。オーバーライドなしの素のデプロイでも認証が ON を保つ。ローカル開発は `.dev.vars` の `ACCESS_REQUIRED="0"` で OFF を維持する**」旨へ改める（コメントが状態について嘘をつかないように・真）。

> **前提の確認（要件 5.6/5.3 の帰結）**: 反転する時点で本番は既に実 `TEAM_DOMAIN` / `POLICY_AUD` を用いて ON 運用に達している（§2）。`wrangler.jsonc` に残すプレースホルダ値（`https://<team>.cloudflareaccess.com` / `<access-app-aud>`）を実値へ差し替えるかは Deployment_Config の投入方式（デプロイ時オーバーライドを継続するか、リポジトリへ実値を記録するか）の判断に従う。**本手順は `ACCESS_REQUIRED` の既定反転のみを規定する**。プレースホルダのままリポジトリへ実値を持たない方針であれば、実値の投入は引き続きデプロイ時オーバーライドが担う（既定が ON になったことで「認証を有効化するか」の判断だけがオーバーライド不要になる）。

### 手順 2. `.dev.vars` にローカル OFF を明示する

`.dev.vars`（git 追跡外・ローカルの `wrangler dev` と vitest workers pool が読む）へ `ACCESS_REQUIRED="0"` を追記し、ローカル開発環境を OFF に固定する。既定が ON になった以上、この明示がなければローカル `pnpm dev` まで認証 ON になり、合鍵 URL 相当での開発ができなくなる。

現在の `.dev.vars`（`ADMIN_TOKEN` のみ）:

```
ADMIN_TOKEN=<ローカル dev 用の Bearer トークン>
```

追記後:

```
ADMIN_TOKEN=<ローカル dev 用の Bearer トークン>
# 既定反転（要件5.7）後、リポジトリ既定 ACCESS_REQUIRED は "1"（本番 ON）。
# ローカル開発は OFF を明示して合鍵 URL 相当で継続する。
ACCESS_REQUIRED="0"
```

> `.dev.vars` は `.gitignore` 済みでリポジトリに乗らない。ゆえにこのローカル OFF 明示は**各開発者の手元でそれぞれ行う必要がある**。本手順の存在（およびチーム内での周知）がその手当てにあたる。ローカルでも意図的に ON を試したいときは、この行を一時的に `"1"` にする（実 `TEAM_DOMAIN` / `POLICY_AUD` の投入が別途必要）。

### 手順 3. `wrangler.jsonc` を編集したら必ず型を再生成する

`wrangler.jsonc` の `vars` を変更したため、tooling 規律（`.kiro/steering/tooling.md`・要件 5.4）に従い `Env` 型を再生成する。

```sh
pnpm cf-typegen
```

これは `wrangler types` を実行し `worker-configuration.d.ts` を更新する。`wrangler.jsonc` は Workers 設定の**単一の正本**であり、設定と型の同期を欠かさない。再生成が失敗した場合は反転を完了とみなさず、失敗原因を解消してから再実行する（要件 5.5 の精神）。`.dev.vars` の変更は型に影響しないため、`.dev.vars` だけの変更では再生成は不要——ただし本手順では手順 1 で `wrangler.jsonc` を変更しているため再生成は必須。

### 手順 4. 検証してデプロイする

- `pnpm typecheck`（`tsc --noEmit`）が通ること（再生成した `Env` 型と整合）。
- 本番へデプロイ（`wrangler deploy` または `pnpm build` → `wrangler deploy`）を**オーバーライドなし**で行い、`ACCESS_REQUIRED` が既定 `"1"` として反映され認証が ON を保つことを確認する。
- ローカルで `pnpm dev` を起動し、`.dev.vars` の `ACCESS_REQUIRED="0"` により合鍵 URL 相当（JWT 検証を経ない接続）で開発できることを確認する。

## 2. 反転の実行可否判断（安定運用到達の基準・運用判断）

`wrangler.jsonc` / `.dev.vars` の編集はコードだが、**反転してよいか否かの判断は運用判断**であり、本手続きに含める。以下のすべてを満たしたときに「本番が安定運用に達した」とみなし、§1 の編集を実行してよい。ひとつでも欠けるなら移行期を継続する（既定は `"0"` のまま・オーバーライドで本番のみ ON を維持）。

判断基準（すべて満たすこと）:

- [ ] **本番が実設定値で ON 運用に達している**: 実 `TEAM_DOMAIN` / `POLICY_AUD`（プレースホルダでない実値）を投入し、有効化ガード（`enablementReadiness`）を通過した状態で本番 `ACCESS_REQUIRED="1"` が稼働している（要件 5.1/5.2/5.3・5.6）。
- [ ] **2 IdP 経路が本番で成立している**: whereami 経路（合成 email）・EntraID 経路（実 email）の双方で、認証から店舗接続までが本番で到達実績を持つ（要件 1・D-2）。
- [ ] **バイパス防御が作動している**: 未認証直叩き（`/s/{storeId}/ws` 等）が 403 で拒否され店舗 DO に到達しないことが、能動プローブ（既定 5 分周期）で継続的に確認できている（要件 8.7・「静かな認証 OFF」への退行が起きていない）。
- [ ] **系統性障害が観測されていない**: whereami 経路の Workers Logs パッシブ指標（`/s/*/ws` の 403 レート・WebSocket アップグレード成功数）が正常域に収まった状態が、切戻し（要件 1.3・検出から 5 分以内に `"0"`）を要さずに**一定期間**継続している。「一定期間」の具体値は運用者が本番トラフィックの実情に照らして定める（例: 連続する複数営業日にわたり切戻し発火ゼロ）。
- [ ] **切戻し手順が依然として有効**: 反転後も系統性障害を検出したら `ACCESS_REQUIRED` を `"0"` へ戻せる（反転後は「素のデプロイで ON」が既定になるため、緊急切戻しはデプロイ時オーバーライドで一時的に `"0"` を与えるか、既定を戻す再デプロイで行う。可逆性は保たれる・要件 1.3/1.6）。

上記が揃わないうちは反転しない。**移行期の footgun（素のデプロイが OFF に戻る）を受容するのは、まさに安定運用到達までの過渡的な代償**であり、到達を待たずに既定を ON にすると、まだ不安定な本番で認証 OFF への可逆な切戻しがしにくくなる（既定が ON だと切戻しがオーバーライド操作になる）。ゲート通過の判断は、この過渡的代償を終える価値があると運用者が判断したときに下す。

---

## 3. 反転後の状態（終着点の不変点）

反転が完了した後、以下が新たな不変点となる。

- **本番**: オーバーライドなしの素のデプロイでも `ACCESS_REQUIRED="1"`（ON）を保つ。認証を黙って OFF に戻す退行余地が構造から消えている。
- **ローカル**: `.dev.vars` の `ACCESS_REQUIRED="0"` により OFF を維持。合鍵 URL 相当で開発を継続できる（本番のみ ON・ローカルは OFF の非対称は `.dev.vars` が明示的に固定する）。
- **コード**: アプリコードのロジックは反転の前後で不変（切替は `vars` の値のみ・3 分岐はいずれも実行時に `env.ACCESS_REQUIRED` を読む・要件 10.1）。
- **型**: `worker-configuration.d.ts` は `pnpm cf-typegen` で `wrangler.jsonc` と同期済み。

この状態をもって Deployment_Config の段階的有効化は終着点に達する。以後、移行期のデプロイ時オーバーライド（`ACCESS_REQUIRED` を ON にするための）依存は解消される。
