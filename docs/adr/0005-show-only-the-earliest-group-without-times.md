# 提案は店舗全体で最早の群だけを出し、時刻を見せず、入れてよい瞬間に現れる

釜ごとに「次の 1 件」を時刻付きで出す形（slot-suggested-start）は、放置すると全提案が `now` へ収束し、順序と間隔という計画の中身が画面から消えた。間隔を保って追随させる案（lapsed-suggestion-timing）も検討し実装したが、根本は「複数の提案を同時に時刻で描く」ことにあると判断し、次のように改める。

- 出すのは **店舗全体で最早の群** だけ（群の中で最も早い startAt 順）。群の全員を出す。担当外の端末は空白。端末同士の同期機構は要らない——全端末が同じ配列から同じ最小を取る。
- 提案は **startAt の 60 秒前に薄く現れ（語なし）、startAt で濃くなり `now`** と描く。60 秒は麺を準備する猶予で、domain の定数。時刻（秒読み・壁時計・間隔）は一切描かない。
- 薄くても押せる（提案は指示ではない）。走行中・茹で上がりのカードには出さない。次の群は「現在の群の最初の 1 本が始まった」かつ「自身の 60 秒前が来た」で現れる。群は可視化しない。
- 提案されていない品目を品目として始める口は、釜のラジアルに店舗全体の待ち行列（到着順）として足す。レールは事実の一覧のまま。

「計画は待てと言ってよい」と「時刻を出さない」を両立させる方法は、出現そのものを合図にする以外にない。時刻を出せば減らない秒読みか間隔の表示が要り、どちらも嘘か認知負荷を生む。

## Considered Options

- **釜ごとに次の 1 件**（現行）: 複数の時刻が並び、放置で収束する。
- **錨を現在へ繰り上げて間隔を保つ**（lapsed-suggestion-timing）: 正しいが、見せる情報が多い。担当外に錨がある端末で「+3:00」の基準が読めない。
- **担当範囲で最早の群**: 各端末に常に「自分の次」があるが、同じ計画が端末ごとに違う順で見える。店舗全体を選び、空白を受け入れた。

## Consequences

- `lapsed-suggestion-timing` は当初「マージしない」としたが #27 としてマージされていた（2026-09-04 に実測）。本 ADR の表示（lift-group-display）が `planAnchor` / `suggestionTiming` を撤去して置き換える。
- 現場が「次はどの釜か」を先読みする手段は画面から消える。全体の量感はレールが担う。
