# 卓同期項（Table_Lag）の秒換算だけ切り上げる。wait の切り捨てと規則を分ける

目的関数は整数の秒で閉じる。Σ Wait_Time と既存の許容超過項は `toWholeSeconds`（切り捨て）で秒へ落とし、その注記は「単位を落とす規則を二つ持てば同じ時間差が項によって違う秒数になる」と規則の一本化を求めていた。本判断はそれに反して、新しい卓同期項（Table_Lag の和）だけを **切り上げ** にする。

理由は、切り捨てで揃えると「揃えた計画の 1 本を 1 ms だけ早めた外部計画」が採用されることにある。`serveAt − arrivalTime` がちょうど秒の倍数だった品目では wait の切り捨てが 1 減り、lag は `floor(1 ms) = 0` で増えない。差し引き 1 点「真に良い」のでゲートを通り、採用された計画は 1 ms だけ揃っていない。client は `startAt + 茹で秒` の等号で群を組む（ADR-0004）ので、この 1 ms で群が割れる。目的関数が守るべき一致を、単位の丸めが破る。切り上げなら任意の Δ > 0 に対し lag が `w_table × ceil(Δ)` 増え、wait の節約は高々 `ceil(Δ)` なので、`w_table ≥ 2` の下で損か同値になり、真に良くはならない（Arms_Overflow が立っている一片では超過項が `w_table − 1` 減って最悪で同値になるが、同値はゲートが棄却する。超過が無ければ真に損）。

規則が二つあることの正当性は役割の違いにある。wait は水準（どれだけ待ったか）で、秒未満は人の知覚の粒度に無いから切り捨てる。lag は逸脱の罰で、ゼロでない差はすべて 1 秒以上として計上されなければ「ずらす得」が残る。差がちょうど 0 のときだけ 0 になることは切り上げでも保たれる（下限 0 は破れない）。

## Considered Options

- **全項をミリ秒で計算する**: 整数のまま丸めが消えるが、釜距離項（無単位の 10 / 14 / 24）と桁が 3 つずれ、`w_affinity` の校正が意味を失う。採らない。
- **切り捨てで統一する（既存の注記どおり）**: 上の 1 ms の穴が開く。採らない。

## Consequences

- 性質「散らした計画は揃えた計画より真に良くならない（Arms_Overflow が無ければ真に大きい）」は 1 ms のずれでも成り立つ。PBT は Δ を 1〜999 ms と 1 秒以上の両域で走らせ、切り捨てに戻した実装はここで落ちる。
- `toWholeSeconds` の注記は「水準は切り捨て・逸脱の罰は切り上げ」の二役へ書き換える。
