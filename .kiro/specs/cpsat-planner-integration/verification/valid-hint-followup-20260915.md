# hint修正後のレビュー対応と再検証（2026-09-15）

先行修正は [hint-lift-window-fix-20260915.md](hint-lift-window-fix-20260915.md)。
独立レビューで再現確認された修正に対し、無効な指定・配置不能を黙って返さないよう補強した。

## レビューの3点への対応

`experiments/cpsat-workers/tuning/schedule.ts` の `formulate` 入口で次を検査する。

- `hardLiftCap: false` は `cumulativeLift: false` と併用しなければ例外。
- `cumulativeLift: false` は `leanPairs: false` と併用しなければ例外。
  旧方式の上げ窓は組ごとのループ内で作るため、この指定も必要だった。

`--legacy-lift-cap` は従来のまま `hardLiftCap: false` を渡すので、通常のCLI経路では
モデル構築が明示的に失敗する。これまでのように、効いていない指定で解や品質指標を返さない。
旧方式のモデルを直接比較する場合は、上記3設定を明示する。
「旧方式は構築できる」だけでなく、同じ過負荷のseedがハード時は `INFEASIBLE`、
ソフト時は実行可能になることを実WASMで検査し、切り替えが実際に制約へ届くことも確認する。

`firstFitAt` は返却直前に `fits` を表明し、容量に収まらなければ例外にする。
例外には需要・容量・探索開始時刻・最後の候補時刻を含める。
負荷がない場合と、既存の負荷を通過しても収まらない場合の両方を試験する。
この表明はモデル自体の実行不能を証明するものではなく、**その容量で貪欲hintを作れなかった**ことを示す。

`orderedHint` の宣言コメントと、前回の釜を使うhintのコメントを訂正した。
hint自体は釜や時刻を固定しないが、hintの上がり時刻がクラスタ数の既定値に影響するため、
モデル全体の解集合が不変だとは主張しない。非単調性の原因を探索範囲だけに帰していた記述も外した。

## Headの目的値を返却ベクトルから再計算

対象は `284_20260905_1945_2145.jsonl` / `2026-09-05T12:12:22.000Z` の1件。
本番コードの返却形式を変えず、一時的なbundle内の診断で
`sum(coefficient * solution[variable])` を計算した。正規の `validateSolution` も通る解である。

| 指標 | 自由求解 | 前回の釜へ固定 |
|---|---:|---:|
| Headの釜 | 9,11 | 6,11 |
| 状態 | FEASIBLE | FEASIBLE |
| 報告目的値 | 262,542 | 253,448 |
| **返却ベクトルからの再計算値** | **262,542** | **253,448** |
| engineの重み付き合計 | 11,398.4 | 11,831.4 |
| 釜の変更数（全対象） | 1 | 3 |

比較の検算：目的関数の係数列・変数の定義域・区間列は一致した。
固定モデルは自由モデルの全制約を保持し、追加分は `variable[240] = 6` と
`variable[256] = 11` の2本だけだった。したがって固定側の解は自由側にも実行可能であり、
同じ目的式で9,094小さい。

この1件については、Headを動かすことがモデル上不可避な取引だったとは言えない。
自由求解が予算内に、既に存在するより良い解を見つけられなかったことを確認できた。
FEASIBLE同士の比較なので、最適値や全局面の探索品質については結論しない。
Headをハード固定する変更も、試験の期待値を緩める変更も行っていない。

結果は [head-objective-audit-20260915.json](head-objective-audit-20260915.json)、
診断の差分は [head-objective-audit-20260915.patch](head-objective-audit-20260915.patch)。
再実行時は通常のrunnerのコピーに差分を適用する。既存のソースは編集しない。

```sh

patch experiments/cpsat-workers/quality/objective-audit.tmp.mjs < .kiro/specs/cpsat-planner-integration/verification/head-objective-audit-20260915.patch
```

### 非単調性は残った

100→120で逆転は5.82→9.18、240→320で3.77→5.13。
**実行不能なhintを解消しても、120と320の窪みは両方とも残った。**
「実行不能なhintだけが非単調性を生んでいた」という説明では今回の観測を説明できない。
過去に実行不能が探索へ影響していなかった、とまで結論するものではない。

ここで測る伝票の逆転は `bill-wait.ts` の伝票全組の指標であり、
モデルの費用項は購入順で隣接する杯の逆転である。この差と、FEASIBLEでの探索打ち切りが残っている。
表の非単調性だけから、目的関数か探索のどちらか一方を原因と断定しない。
Headの1件は、別途同一目的式でより良い実行可能解の存在を確認した証拠である。

共通71局面では、960は480より逆転・広がり・変更費用・最長待ち・最古3伝票の平均が小さい。

逆転は17→0、伝票内の広がりは517→45秒になる。

今回の再測定でも960は平均の順序指標で有力だが、局面ごとの待ちの悪化まで含めると480を一律に支配していない。
本番係数は変更していない。丸め差とHeadの既知の失敗も、解決済みとは扱わない。
