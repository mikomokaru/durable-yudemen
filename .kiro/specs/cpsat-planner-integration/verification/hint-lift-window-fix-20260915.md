# hint の上げ窓整合性の修正（2026-09-15）

> レビュー指摘への追加対応、修正後hintでの9点掃引、Headの目的値の再計算は
> [valid-hint-followup-20260915.md](valid-hint-followup-20260915.md) を参照。

## 変更と原因

通常の貪欲 hint が、既に決まっている走行中の上げ窓に衝突する配置を作っていた。
`experiments/cpsat-workers/tuning/schedule.ts` の局所的な修正で対応した。
係数、探索予算、`orderedHint` / `bill*` の既定値は変更していない。

1. `fits` は候補時刻 `at` の負荷だけを見ていた。一方、モデルの cumulative は
   `[at, at + liftWindow)` 全体で容量を課す。候補の直後に走行中の麺が上がると、
   hint は許してもモデルは許さない。候補時刻と、その区間内にある既存の上がり時刻をすべて検査する。
2. `firstFitAt` も将来の重複区間を障害物に含め、重複する区間の最初の終了点まで候補を進める。
   従来のフィルタでは、候補より前の負荷がゼロなら衝突していてもその場で終了していた。
3. 手伝いの hint は未着手の杯同士しか数えていなかった。走行中・過去の固定負荷も含め、
   同じ全区間検査で手伝いの要否を決める。外から与えた配置がハード容量内にあっても、
   手伝いなしではソフト側 cumulative を破るケースを修正した。

例：腕2本、上げ窓45秒、走行中4杯が300秒に上がる局面で、新しい杯を278秒に上げる。
278秒の直前には負荷がなくても、300秒にはその杯の上げ区間が残るため、
固定分4本＋新規1本でハード容量4本を超える。修正後の貪欲 hint は345秒まで送る。
一方、255秒の上がりなら区間の右端がちょうど300秒なので、早い配置を維持する。

釜の占有・上げ窓のハード制約を緩めてはいない。ただし既存の `clusterCount` は
hint の相異なる上がり時刻数に依存するため、**hint が変わってもモデル全体が不変とは言えない**。
該当する hint のコメントも訂正した。この依存そのものは今回変更していない。

## 制約の切り分け

`tests/cpsat-hint-feasibility.example.test.ts` は、実際の `formulate` と protobuf を
固定版・凍結時計の WASM に通し、与えた hint を固定して解く。
ソルバーによる hint の修復では試験が通らない形にした。

- 将来の満杯窓、時刻のずれた走行中＋2釜の杯は修正前に `INFEASIBLE`、配置修正後に成功。
- 固定負荷のため手伝いが要る seed は、手伝い判定の修正前に `INFEASIBLE`、修正後に成功。
- 不正な seed を明示すると、修正後も `INFEASIBLE`。
  テスト内のモデルのコピーから cumulative だけを外すと成功する。制約を弱めて通した修正ではない。
- 早く出せる杯を維持し、上げ窓の半開区間の境界も検査する。

過去の切り分けにある `--legacy-lift-cap` には注意が要る。
このフラグは `hardLiftCap: false` を渡すが、既定の cumulative 経路の
`withBands(h.arms + 2, ...)` はその値に関わらず残る。
したがって「そのフラグで変わらなかった」だけでは上げ窓制約を原因から除外できない。
今回の負の対照では、実際に cumulative を除いたモデルと比較している。

## 72局面に残った1件：実時刻とモデル秒の丸め差

残る失敗は `342_20260907_1345_1545.jsonl` / `2026-09-07T06:04:52.000Z`。
hint固定は `OPTIMAL`、自由求解の解はモデルの検証を通るが、返却前の `withinLiftCap` に落ちる。
UNKNOWNとは異なる失敗である。

当該1局面だけの再生に一時的な診断を差し込み、次の実値を得た。
一時診断は削除済みで、`src/cpsat/plan.ts` 自体は変更していない。

- 新しい1杯の上がり：`1789463669000` ms。
- 固定の6杯の上がり：`1789463713226` ms。
- 実際の差は **44,226 ms**。同じ45秒窓に入るので受理側が拒否するのが正しい。
- モデルの走行中終了は秒へ切り上げて `1789463714000` ms相当になり、差がちょうど45秒に変わる。
  モデルは境界で重ならないと判定する。

釜を早く空けないための終了時刻の切り上げが、上げ窓の前側では安全側になっていない。
解消には、釜の占有終了と実際の麺揚げ時刻の写像を分ける必要がある。
単に釜の終了時刻を切り下げたり、返却前の検査を外したりしてはならない。
この修正とHeadの安定性は残作業として記録する。
