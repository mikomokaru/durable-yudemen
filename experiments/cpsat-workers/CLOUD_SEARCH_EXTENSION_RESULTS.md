### 初期値が最良に残ることの解釈

外側採点の実装は `schedule.ts` の
`total({ ...features, orderFragments: 0, orderDistance: 0 }, DEFAULTS)` に
視覚的な散らかりの時間積分を加えたもの。
全候補に同じ基準を適用しており、初期値であること自体への加点はない。
ただし、初期値は外側の大部分と同じ重みで計画を作るため、この採点基準との整合性が高い。

内側は限られた品目を対象とした探索量上限付き再計画、外側は履歴全体と別の空間時間評価なので、
両者は同一問題ではなく、他の係数が勝つ余地はある。一方、初期値も他候補も同等な無作為標本だと
仮定した確率計算は適用できない。12変数に対する少数の広い範囲の候補比較でもある。
今回の非初期値8候補では、arm超過とclusterの重みはそれぞれ7候補で初期値より大きかった。
初期値近傍や低い重み側を十分に探索できたとはいえない。
初期値が残った事実は「人のpainを秒へ換算する初期値が正しい」との実証ではない。

この探索で調整しているのは、**固定した仮説の評価基準に対して、有限予算のWASMプランナーが
良い計画を出すための内部係数**。評価基準そのものの妥当性を学習しているわけではない。
実行途中で採点を変えず、スコア・待ち時間・負荷特徴量を分けて判断材料にする。
